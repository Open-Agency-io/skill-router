# Code of Conduct

This is a concise behavior and moderation policy for the Skill Router
repository. It is deliberately short and project-specific: it is **not** the
Contributor Covenant, because this repository does not (yet) have a
designated private reporting channel, and a code of conduct that names one
would be a false claim. The limitation is stated explicitly at the end.

## Expected behavior

- Be respectful, constructive, and precise. Technical disagreement is
  welcome; personal attacks are not.
- Assume good faith, and argue from evidence: versions, platforms, logs, and
  minimal reproductions beat speculation.
- Keep reports proportionate to the project: this is a small open-source
  tool, not a 24/7 support desk.
- Respect the project's documented boundaries: Linux is the gated platform,
  macOS is developer-tested, Windows is unsupported, and the package is not
  published to npm yet. Use issue and pull-request templates as written.

## Unacceptable behavior

- Harassment, discrimination, personal attacks, or sustained rudeness in any
  repository space (issues, pull requests, reviews, commit messages, or any
  public forum tied to this repository).
- Publishing, or demanding that others publish, private information —
  credentials, tokens, request bodies, personal data — in any public space
  tied to this repository.
- Deliberately malicious participation: bad-faith bug reports, spam,
  off-topic promotion, or attempts to use this repository's issues or
  releases to distribute malware or squatted packages.
- Impersonating maintainers or misrepresenting affiliation with this
  project.

## Scope

This policy applies to participation in this repository and in official
spaces tied to it: issues, pull requests, reviews, releases, and any future
official discussion spaces pointed to from this repository. It does not
govern private conversations, other projects, or third-party spaces.

## Enforcement

Maintainers may moderate repository participation when this policy is
violated. Proportional responses include:

1. a reminder or request to edit/close a thread;
2. hiding or locking a conversation;
3. closing, labeling, or rejecting an issue or pull request;
4. temporary or permanent blocking from repository participation;
5. for malicious or illegal content, reporting to the hosting platform
  (GitHub) under its own terms.

Enforcement decisions are made by the maintainers, case by case, and are
explained publicly in the affected thread where doing so is appropriate and
does not expose private information. There is **no** enforcement
response-time SLA.

## Limitations — read honestly

- **No private conduct-reporting channel is designated yet.** A private
  channel for sensitive conduct reports (harassment involving personal
  information, for example) does not exist for this repository, and this
  file deliberately does not invent an email address or endpoint for one.
  Designating such a channel is an external, human decision that must be
  resolved **before** this project claims one exists — until then, conduct
  concerns can only be raised through whatever private contact method a
  maintainer actually lists on their public GitHub profile at the time, or,
  when the matter is not sensitive, through a normal repository issue that
  itself contains no private information.
- This policy may be amended by the maintainers; material changes will be
  recorded in the repository history.
